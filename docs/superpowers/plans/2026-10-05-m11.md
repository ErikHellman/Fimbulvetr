# M11 — Completion and ship — implementation plan

## Context

M10 is built and up as PR #18, stacked on M9's PR #17. Under the user's standing order (2026-10-05) every remaining milestone is built in turn, one stacked PR each. The M11 brief (`docs/briefs/m11.md`) takes Claude's recommended answer to each question. This plan follows the M10 plan's rhythm.

### Working rules (as in M10)
- **Branch:** `claude/m11-completion`, cut from `claude/m10-utgard`. One commit per task or small group of tasks, with `pnpm check` green before each. TDD for core, content and art.
- **Shell work:** read the matching `node_modules/phaser/skills/<topic>/SKILL.md` first.
- **Pushing:** push at the end of each part. One PR for all of M11, based on `claude/m10-utgard`. GitHub Pages stays off.
- **Ledgers:** `docs/superpowers/ledgers/2026-10-05-m11a-completion.md` and `…-m11b-ship.md`.

## System designs

1. **Counting conditions (M11a).** `Cond` gains `{ k: 'pieces'; gte }` (heart pieces found, `world.pieces.length`) and `{ k: 'warps'; gte }` (warp stones lit, `world.warps.length`). Both are pure reads of the saved state.
2. **Achievements (M11a).** `src/core/progress/achievements.ts`: `AchievementDef { id, name, hint, when: Cond }` and `earned(defs, ctx): AchievementId[]`. Content: `ACHIEVEMENTS` ids in `content/ids.ts` (append-only, since the browser stores them) and `content/achievements.ts` with the 24 defs. "Every side quest" is built from `SIDE_QUESTS` (a content list) as an `all` of `quest gte last-stage` conditions. "Every warp stone" and "every heart piece" use the totals from content.
3. **The achievement store and toast (M11a, shell).** `shell/platform/achievements.ts`: parse and store `fimbulvetr.achievements.v1` (an id list; unknown ids dropped; storage errors swallowed). PlayScene checks every 30 ticks while playing, stores new ones, and hands them to the UI scene, which shows a toast at the top for three seconds, one at a time. The title menu gains "Achievements" (a list page), and the pause menu's Quests tab gains the progress footer.
4. **The rune-record (M11a).** `q_record`, from `st_halvar_confessed`: Gyða asks (`q_record_asked`). Four `bauta` props, one each in a Myrkviðr, Haugar, Sævatn and Hrímfjöll screen, are read with interact (a script per stone: a line naming the fallen, and `q_record` +1 through a latch flag per stone so a stone counts once). At 4, Gyða cuts the names in and gives `hp_record`.
5. **The spring feast (M11a).** `q_feast`, from `st_game_done`: Halvar asks for mead-honey (Sigrún), a burbot (Kári, or one caught) and a cask (the Refuge's keeper). Each is a dialogue hand-over setting a flag. With all three, talking to Halvar in the evening runs `end_feast`: the villagers at the long table, a line each from a few of them, and `hp_feast`.
6. **World pieces and verses (M11a).** Four `piece` things, each placed behind a late tool in an existing screen, plus four verses in `VERSES` (Bragi sells them as before; new `w_verse_*` flags). The solver tests prove each piece unreachable without its tool and reachable with it.
7. **Drawn font sizes (M11b).** `src/art/font.ts` gains `FONT_SIZES` (`normal` 1×, `large` 1.5×, `larger` 2×) and `glyphsAt(size)`, scaling each glyph raster by nearest neighbour with fixed row and column maps; `textWidth`, `layoutText` and the metrics take the size. The shell registers three bitmap fonts. `Settings.textSize` becomes `'normal' | 'large' | 'larger'` (a stored number falls back to normal) and joins the settings menu. UiScene sets the font of the speaker tab, the body, the choices and the card text by the setting, and sizes the box to the laid-out lines.
8. **The title rune (M11b).** The font gains `ᛟ`. `SaveSummary` gains `done` (from the save's `st_game_done`), and `summaryLine` prefixes the rune.
9. **The Safari and performance pass (M11b).** An audit table in the ledger, a fix per finding, and `tests/sim/bench.test.ts` (ticks on the busiest screens under a generous budget, so CI does not flake, but a regression of an order of magnitude fails).

## Core interface changes (CLAUDE.md "plan first")

`GameState`, `SaveData`, `Sim` and `ContentDb` do not change, and `SAVE_VERSION` stays 1. `Cond` gains two kinds (a union widening; every switch over it is exhaustive, so typecheck finds each place). New ids are appended: quests `q_record`, `q_feast`; flags for both quests, the four stones, the hand-overs and four verses; heart pieces; scripts; the `bauta` prop; the achievements list. Fixtures `v1-m11a.json` and `v1-m11b.json` are added, and every older one must still load.
