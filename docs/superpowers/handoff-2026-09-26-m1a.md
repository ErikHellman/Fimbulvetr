## How to run and try it

```bash
pnpm dev                              # new game: dawn on day 1 in the longhouse
pnpm dev -- then open ?preset=day2    # also day3, night3 (sleep → the raid beat), m0 (test lands)
?dev=gallery                          # every generated frame and tile
?screen=test_b&preset=m0              # the demo corner: sign, pots, logs, grass, hut door, stall
PW_CHROMIUM_PATH=/opt/pw-browsers/chromium pnpm e2e --project=chromium   # in this cloud container
```

**Controls** (unchanged from M0):
- Movement and combat as in M0.
- E: talk, read, lift, throw (while moving) or set down (standing still).
- Enter or E: advance text. Up and Down: choices and shop rows. Escape: leave the shop.

## Notes for the next session

- **Golden hash.** `tests/sim/golden.test.ts` pins one run's hash. It was re-recorded twice on purpose (the hash gained story and id-counter coverage; test_b gained props). Re-record it only when a change is meant to alter the simulation, and say so in the commit.
- **Route test.** `tests/sim/route_m1a.test.ts` is the M1a autopilot. M1b should extend the pattern with a route from the raid to the Myrkviðr road.
- **Content tables that grow as content is written** (dialogue, scripts, npcs, quests, shops) are `Partial` records. `tests/content/story.test.ts` checks every reference and every flag read against the flags that are set.
- **Saves.** Nothing in M1a changed the save format (still v1). `tests/fixtures/saves/v1-m1a.json` is the milestone fixture. M1c must normalise `dungeons.d1` before reading it (M0 carry-over).
- **Sheep.** Sheep are pushed along the hero's walking direction. If the playtest finds herding too easy or too hard, tune `SHEEP_FLEE`, `SHEEP_FLEE_RADIUS` and the push weight in `src/core/actors/critters.ts`, then re-run the route test.
